GitHub Spec Kit is being adopted into the Storylane repo (owner's explicit choice over a sandbox). The 住み分け was approved 2026-08-13 with these bindings:

- `spec/` stays the permanent product-spec source of truth; `specs/NNN/` holds Spec Kit drafts, left as history after permanent content is folded into `spec/`.
- **For features run through Spec Kit, `specs/NNN/` is the design doc — no duplicate Backlog doc-N is created** (this was the conflict the plan missed: doc-N was the prior home for feature designs).
- Backlog.md remains the only execution tracker. **Superseded 2026-08-13 by the owner:** the original verdict said `speckit-implement`/`speckit-taskstoissues`/`speckit-converge` are deleted outright, but the owner then reframed the adoption as an observation trial (how does native Spec Kit land in an existing project, as input for adopting it elsewhere) — so all skills stay installed for ONE full-pipeline trial run on a small no-tables/no-RLS feature, and the delete-or-keep decision happens after that trial (CLAUDE.md "Spec Kit (experimental)"). Exception: `speckit-constitution` was deleted immediately — it regenerates the hand-curated constitution from the generic template, and no trial needs it.
- `constitution.md` is a hand-curated pointer file (CLAUDE.md / decision-1 / spec/ux-principles.md win on conflict); never regenerated by `/speckit-constitution`.
- Advisor pre-implementation review and the ux-principles design-review gate apply unchanged to speckit-plan outputs.

**Why:** kept the review/RLS/model-assignment gates and the public-repo name rule intact while adding a drafting workflow; deletion-over-prohibition avoids skill-index token cost and unenforceable rules.

**How to apply:** when reviewing a plan for a Spec Kit-driven feature, expect the design in `specs/NNN/plan.md`; flag any duplicate doc-N, a constitution.md that restates (rather than points to) the canon, or — once the post-trial decision lands — any resurrection of whichever skills get removed then. During the trial, implement/converge/taskstoissues being present is intentional, not a violation. See [[owner-review-preferences]].
